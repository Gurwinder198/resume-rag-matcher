# Milestone 2 — Resume RAG & Job Matching: Assignment Spec

Source: assignment brief provided by the user, 2026-10-18. Kept verbatim (lightly
reformatted) so the plan can be checked against it.

## Learning Objectives

- Implement document chunking and embedding
- Build vector databases
- Create retrieval pipelines
- Understand semantic search

## Assignment Requirements

### Part A: RAG System Setup (50%)

Create `resume_rag.py`:

1. **Document Processing Pipeline**
   - Load resumes using file system tools from Milestone 1
   - Chunk documents intelligently (preserve sections like Education, Experience)
   - Generate embeddings using OpenAI/Cohere/HuggingFace models
   - Store in vector database (ChromaDB, Pinecone, or Weaviate)
2. **Metadata Extraction**
   - Extract key fields: Name, Skills, Experience Years, Education
   - Store metadata alongside embeddings for filtering

### Part B: Job Matching Engine (50%)

Create `job_matcher.py`:

1. **Semantic Search**
   - Accept job description as input
   - Convert JD to embedding
   - Retrieve top-K similar resumes (K=10)
   - Implement hybrid search (semantic + keyword for critical skills)
2. **Ranking & Scoring**
   - Score matches (0-100 scale)
   - Provide match reasoning (which sections matched)
   - Filter by must-have requirements (e.g., "5+ years Python")

### Output Format

```json
{
  "job_description": "...",
  "top_matches": [
    {
      "candidate_name": "John Doe",
      "resume_path": "resumes/john_doe.pdf",
      "match_score": 92,
      "matched_skills": ["Python", "Machine Learning"],
      "relevant_excerpts": ["..."],
      "reasoning": "Strong match for ML experience..."
    }
  ]
}
```

### Deliverables

- Complete RAG implementation
- Dataset: 30+ diverse resumes, 5+ job descriptions
- Jupyter notebook with experimentation and analysis
- Performance metrics: retrieval accuracy, latency
- Demo video (3-4 minutes), using OpenRouter

## Architecture decisions made for this plan

- **Embeddings:** local HuggingFace `sentence-transformers` (`all-MiniLM-L6-v2`).
  OpenRouter (used in Milestone 1 and for this assignment's LLM calls) is a chat/completions
  proxy — it has no embeddings endpoint, so embeddings must come from HuggingFace directly.
  This also means embedding generation needs no API key.
- **Vector DB:** ChromaDB, `PersistentClient`, local on-disk — no cloud account needed,
  simplest of the three listed options for a local assignment.
- **LLM calls:** OpenRouter (`openrouter` SDK), reusing the Milestone 1 pattern
  (`OPENROUTER_API_KEY` / `OPENROUTER_MODEL` in `.env`) — used for the optional
  LLM-enhanced match reasoning and in the demo.
- **File loading:** `fs_tools.py` ported unchanged from
  `../llm-file-assistant/fs_tools.py` (Milestone 1).
- **Dataset:** synthetic (fictional candidates), generated by
  `scripts/generate_dataset.py`, since no real resumes were supplied — 32 resumes
  across 8 roles, 5 job descriptions, plus a `dataset_manifest.json` ground-truth
  file used for retrieval-accuracy measurement.
